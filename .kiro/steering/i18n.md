# Internationalization (i18n)

## Supported Languages

The `UserSettings.language` type in `src/types.ts` defines the supported set: English (`en`), Portuguese (`pt`), Spanish (`es`), and Italian (`it`). Treat `src/types.ts` as the source of truth for which languages are supported.

## Rules

- Never hardcode user-facing strings in components. Route all display text through `useTranslation()` from `src/i18n/LanguageContext.tsx`.
- When adding a new string, add the key to every supported language dictionary in `src/i18n/translations.ts`. Do not leave a language missing a key.
- If a translation is genuinely pending, add the key to all languages with a best-effort value rather than omitting it, and flag the ones that need review.
- The active language preference is stored in `localStorage` (key `certstudy_language`).
- Keep keys descriptive and grouped by feature area, matching the existing structure in `translations.ts`.

## Verification

- After adding strings, run `bun run build` (or `npm run build`) to ensure the translation types stay consistent and no key is missing across languages.
